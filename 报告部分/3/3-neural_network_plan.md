# 第 4 部分：监督学习神经网络决策规划

## 1. 目标定位

本部分对应项目要求中的“采用监督学习的方式训练一个人工神经网络进行 2048 游戏决策”。目标不是直接超过启发式搜索策略，而是让神经网络学习已有强策略在不同棋盘状态下的动作选择规律，形成一个可以独立给出上、下、左、右四类动作概率的决策模型。

神经网络部分在整体项目中的位置如下：

1. 游戏引擎提供合法状态转移、得分和终局判断。
2. 启发式搜索或进化优化后的启发式智能体作为专家策略。
3. 专家策略自动生成监督学习样本：`棋盘状态 -> 专家动作`。
4. 神经网络学习专家动作分布，并作为新的 `Agent` 接口实现参与评估。
5. 后续强化学习阶段可使用该模型作为初始化策略或对照基线。

## 2. 数据集构建

### 2.1 样本来源

采用当前项目中表现较好的启发式策略作为专家策略。若第 3 部分进化优化后的权重已经稳定，则优先使用进化后的启发式智能体生成标签；否则使用默认启发式智能体生成基础数据集。

每条样本包含：

- `state`：当前 4x4 棋盘。
- `action`：专家策略在当前状态下选择的动作，编码为 `0=up, 1=down, 2=left, 3=right`。
- `valid_actions`：当前状态下合法动作掩码，用于训练和推理时过滤无效动作。
- `score_before`、`max_tile`、`empty_count`：辅助分析字段，不直接作为模型输入的必要项。

### 2.2 采样策略

单纯记录完整对局会导致前期低数值棋盘样本过多，后期高价值棋盘样本不足。因此数据生成采用分层采样：

- 前期状态：最大方块小于 128，保留部分样本。
- 中期状态：最大方块在 128 到 1024 之间，较高比例保留。
- 后期状态：最大方块大于等于 1024，尽量全部保留。

初始规划规模：

- 生成 2,000 到 5,000 局专家对局。
- 目标样本量约 100,000 到 300,000 条。
- 按 `80%/10%/10%` 划分训练集、验证集和测试集。

如果训练时间受限，可先使用 20,000 到 50,000 条样本完成可运行版本，再扩大数据集。

## 3. 状态编码

2048 棋盘数值跨度大，直接输入原始数值会造成尺度不稳定。规划采用 `log2` 编码作为默认输入：

- 空格编码为 `0`。
- 数值 `2, 4, 8, ...` 分别编码为 `1, 2, 3, ...`。
- 将 4x4 棋盘展开为 16 维向量，或保留为 `1x4x4` 张量。
- 输入可除以常数 `16` 做归一化，使特征落在较稳定范围。

备选方案是 one-hot 编码，将每个格子编码为可能指数等级的 one-hot 向量。它表达能力更强，但实现和训练成本略高。第一版优先使用 `log2` 编码，报告中说明选择原因：2048 的相邻等级关系具有数值顺序，`log2` 编码简单且足够表达合并规律。

## 4. 模型结构

### 4.1 首选模型：MLP

考虑到棋盘只有 4x4，第一版使用多层感知机即可满足课程实验要求，训练速度快，也便于和启发式策略对比。

建议结构：

```text
Input: 16
Linear(16, 128) + ReLU
Linear(128, 128) + ReLU
Linear(128, 64) + ReLU
Linear(64, 4)
Output: 4 个动作 logits
```

推理时对非法动作做 mask，将非法动作的 logits 置为极小值，再选择概率最高的合法动作。

### 4.2 备选模型：轻量 CNN

如果 MLP 表现不足，可增加轻量 CNN 对局部合并模式建模：

```text
Input: 1x4x4
Conv2d(1, 32, kernel_size=2) + ReLU
Conv2d(32, 64, kernel_size=2) + ReLU
Flatten
Linear(..., 128) + ReLU
Linear(128, 4)
```

CNN 的优势是可以捕捉相邻格子的局部关系，但 4x4 棋盘很小，卷积结构未必一定优于 MLP。因此规划中将 MLP 作为主线，CNN 作为扩展对照。

## 5. 训练方法

### 5.1 损失函数

使用交叉熵损失：

```text
loss = CrossEntropyLoss(action_logits, expert_action)
```

这是标准多分类监督学习问题，标签来自专家策略的离散动作。

### 5.2 优化器与超参数

推荐初始配置：

- 优化器：Adam。
- 学习率：`1e-3`。
- batch size：`256`。
- epoch：`20` 到 `50`。
- 权重衰减：`1e-5`，用于减少过拟合。
- 早停：验证集准确率连续 5 个 epoch 无提升则停止。

训练过程中保存：

- `best_model.pt`：验证集准确率最高的模型。
- `training_log.csv`：每个 epoch 的训练损失、验证损失、训练准确率、验证准确率。
- `confusion_matrix.png`：动作分类混淆矩阵。

## 6. 评估方案

神经网络不能只看分类准确率，因为最终目标是 2048 游戏表现。因此评估分两层。

### 6.1 离线监督指标

- Top-1 accuracy：模型动作是否等于专家动作。
- 合法动作率：模型输出动作是否合法。
- 各动作召回率：观察是否偏向某些方向。
- 验证集 loss：判断是否过拟合。

### 6.2 在线游戏指标

使用 `eval/evaluate.py` 的多局评估框架，与前面方法保持一致：

- 平均得分。
- 最高得分。
- 平均最大方块。
- 2048 达成率。
- 平均生存步数。

建议每种策略固定随机种子评估 100 局：

1. 默认启发式策略。
2. 进化优化后的启发式策略。
3. 监督学习 MLP。
4. 监督学习 CNN，如果实现扩展版本。

报告重点分析：神经网络的分类准确率较高时，在线得分仍可能低于专家策略，因为少量关键状态动作错误会在 2048 中被后续随机方块放大。

## 7. 代码落地规划

建议新增或扩展以下文件：

- `agent/supervised.py`：实现 `NeuralNetworkAgent`，继承 `Agent`，负责模型加载、状态编码和动作选择。
- `eval/generate_supervised_data.py`：调用专家智能体生成 `state/action/valid_actions` 数据集。
- `eval/train_supervised.py`：训练 MLP/CNN，保存模型和训练日志。
- `eval/evaluate_supervised.py`：加载训练好的模型并运行多局评估。
- `报告部分/3/3-neural_network_plan.md`：记录本规划。
- `报告部分/3/3-neural_network_result.md`：实验完成后记录训练曲线、分类指标和游戏指标。

为避免影响已有启发式和进化优化代码，神经网络部分只通过 `Agent.get_action(board)` 接口接入游戏，不改动 `game/board.py` 的核心逻辑。

## 8. 实施步骤

1. 实现状态编码函数：将 `Board` 转换为 16 维 `log2` 特征。
2. 实现专家数据生成脚本：批量运行启发式智能体并保存样本。
3. 实现 MLP 模型和训练脚本：完成离线分类训练。
4. 实现 `NeuralNetworkAgent`：加载模型并输出合法动作。
5. 接入现有评估流程：统计平均得分、最大方块和生存步数。
6. 补充结果报告：比较监督学习模型与专家策略的差距。
7. 视时间实现 CNN 对照或作为后续强化学习的初始化模型。

## 9. 风险与控制

- 数据偏置：专家对局前期状态过多，会导致模型偏向简单状态。通过分层采样缓解。
- 非法动作：模型可能输出无效方向。推理阶段必须使用合法动作 mask。
- 误差累积：监督学习只模仿专家单步动作，在线运行时遇到训练集中少见状态会退化。通过扩大数据集和加入模型自走状态再标注缓解。
- 训练收益有限：神经网络可能低于启发式搜索。这是合理现象，报告中应强调神经网络的作用是学习策略近似，为强化学习阶段提供模型基础。

## 10. 阶段验收标准

神经网络部分完成后应满足：

- 能自动生成监督学习数据集。
- 能训练并保存一个可加载的 PyTorch 模型。
- `NeuralNetworkAgent` 能独立完成 2048 对局。
- 报告中有训练曲线、分类准确率和至少 100 局游戏评估结果。
- 能与启发式策略、进化优化策略进行同指标对比。
